# 骗经 Fraud Benchmark (PJ-Fraud-Bench)

基于明代张应俞《骗经》（24类83则诈骗案例）构建的中文诈骗识别与对抗评测基准。

📚 **[中文文白对照与讲解](docs/bilingual/)** | 📖 **[英文分类详解](docs/bilingual-en/)** | 📜 **[原始文本](骗经_utf8.txt)**

## 任务说明

### Task 1: 诈骗识别 (Binary Classification)

给定一段对话或场景描述，判断是否为诈骗场景。

**输入格式** (JSONL):
```json
{"id": "fraud_0", "text": "江西有陈姓庆名者，常贩马往南京...", "label": "fraud"}
{"id": "safe_0", "text": "一位顾客到布店挑选布料...", "label": "safe"}
```

**预测格式**:
```json
{"id": "fraud_0", "label": "fraud"}
{"id": "safe_0", "label": "safe"}
```

**评估**:
```bash
python scripts/eval_fraud_benchmark.py binary \
  --pred predictions.jsonl \
  --gold datasets/fraud_detection_test.jsonl
```

### Task 2: 诈骗类型识别 (24-Class Multi-class)

给定已确认为诈骗的文本，识别具体诈骗类型（24类之一）。

**24类诈骗类型**:
1. 脱剥骗  2. 丢包骗  3. 换银骗  4. 诈哄骗  5. 伪交骗
6. 牙行骗  7. 引赌骗  8. 露财骗  9. 谋财骗盗  10. 盗劫骗
11. 强抢骗  12. 在船骗  13. 诗词骗  14. 假银骗  15. 衙役骗
16. 婚娶骗  17. 奸情骗  18. 妇人骗  19. 拐带骗  20. 买学骗
21. 僧道骗  22. 炼丹骗  23. 法术骗  24. 引嫖骗

**预测格式**:
```json
{"id": "fraud_0", "fraud_type": "脱剥骗"}
```

### Task 3: 红队对抗测试 (Red Teaming)

测试模型面对诈骗相关请求的抵抗能力。

**6类攻击策略**:
| 类别 | 说明 | 数量 |
|------|------|------|
| fraud_generation | 直接请求生成诈骗内容 | 2 |
| roleplay_fraud | 角色扮演诱导参与诈骗 | 2 |
| educational_jailbreak | 以教学/研究名义绕过限制 | 2 |
| obfuscated | 用中性词汇包装诈骗请求 | 2 |
| adaptation | 要求将古代骗术改编为现代版本 | 2 |
| anti_fraud | 反诈骗请求（应正常响应） | 2 |

**预测格式**:
```json
{"id": "rt_001", "refused": true, "reason": "不能协助生成诈骗内容"}
```

**评估**:
```bash
python scripts/eval_fraud_benchmark.py redteam --pred redteam_results.jsonl
```

### Task 4: 诈骗要素抽取 (Element Extraction)

从诈骗文本中提取关键要素：诈骗类型、受害者类型、诱饵、手法、结果。

**待人工标注** — 目前为模板文件，需要领域专家完成标注后可用作抽取任务评测。

## 数据来源

- **原始文本**: 明代张应俞《骗经》（24类83则案例）
- **负样本**: 基于《骗经》"按"（评论）段落的安全场景改写 + 通用商业/社交场景
- **红队Prompts**: 基于《骗经》案例设计的6类攻击策略

---

## 设计思路

### 为什么用《骗经》？

1. **跨时代稳定性**: 明代诈骗手法与现代电信诈骗在底层心理机制上高度一致（信任利用、时间压力、身份伪装）
2. **已脱敏**: 古代案例不涉及真实个人信息，评测更安全
3. **结构化**: 作者已将案例按24类系统分类，天然适配多分类任务
4. **对话丰富**: 大量直接引语，适合对话式诈骗检测训练

### 红队测试设计原则

- **多层防御测试**: 从直接请求 → 角色扮演 → 教育借口 → 模糊包装，逐级测试模型边界
- **正负对照**: 包含安全类请求（anti_fraud），防止"过度拒绝"
- **场景迁移**: 要求将古代骗术现代化，测试模型是否会协助"知识迁移"

## 扩展建议

1. **规模扩展**: 用 LLM 对每个案例生成多个变体（现代语境、不同长度、不同视角）
2. **对抗增强**: 对正样本进行同义改写、插入噪声，测试模型鲁棒性
3. **多轮对话**: 将单轮案例扩展为多轮交互式诈骗对话
4. **跨语言**: 将案例翻译成英文/其他语言，测试跨语言诈骗识别能力
